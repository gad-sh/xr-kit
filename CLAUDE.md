# gadxr-kit

Building blocks for WebXR pages with Svelte 5 and A-Frame 1.8: the design system, teleport, fast raycasts, and a starter app. Early days — prefer small, direct changes over new abstractions.

## Running

- pnpm workspace: `packages/ui` (the design system, below), `packages/aframe-blink-controls` (teleport), `packages/aframe-bvh` (fast raycasts), `templates/starter` (the starter app) and `apps/gallery` (below). The three packages are `@gadxr/ui`, `@gadxr/aframe-blink-controls` and `@gadxr/aframe-bvh`, published on npm (see Publishing). An app installs them from npm, or, to work on the kit and the app together, depends on them with `link:` to this folder (e.g. `link:../gadxr-kit/packages/ui`), so a change here shows up there straight away (its dev server may need a restart). Linked packages use this workspace's `node_modules`: Vite dedupes `svelte` at runtime, but svelte-check doesn't, so keep a linking app's svelte version the same as this workspace's (a mismatch shows as a `Snippet` type error in `Modal.svelte` when the app type-checks). Type check: `pnpm check` (svelte-check for the library, the starter and the gallery). Tests: `pnpm test`.
- CI (`.github/workflows/ci.yml`) runs `pnpm check`, `pnpm test`, the library's build and the gallery's build on every pull request and push to `main`; land changes through PRs so it runs before merging and publishing.
- Starter: meant to be copied out (`npx degit gad-sh/xr-kit/templates/starter my-app`), so it depends on version ranges (`^0.1.1`), not `workspace:*`; the root `.npmrc` (`link-workspace-packages=true`) still links the local packages while their versions fit, and `scripts/check-starter-links.mjs` (first step of `pnpm check`) fails if one came from npm instead. **After bumping a package's version, update the starter's range.** Its `.gitignore` is for the copy. Run it: `pnpm dev` (or `pnpm --filter starter dev`), **https** via `vite-plugin-mkcert`; takes the next port if 5173 is busy. For a throwaway test server use another port (`--port 5199 --strictPort`) so the user's own servers aren't disturbed. Build check without touching `dist/`: from `templates/starter`, `./node_modules/.bin/vite build --outDir <scratch dir> --emptyOutDir`.
- Gallery: `pnpm gallery` (`apps/gallery`, plain http). Every component in 2D (top) and 3D (bottom), sharing state: use it to check visual changes to the library. `.github/workflows/gallery.yml` builds it and deploys it to GitHub Pages on every push to `main` (https://gad-sh.github.io/xr-kit/); `base: './'` in its `vite.config.ts` keeps asset URLs working under `/xr-kit/`.

## Packages

- `packages/aframe-blink-controls` — teleport (`blink-controls`): our fork of `jure/aframe-blink-controls` (upstream `main` + four fixes, see its README). The fork is `gad-sh/aframe-blink-controls` on GitHub, cloned at `~/Code/gad-aframe-blink-controls`; the fixes are on its `gadxr` branch (pushed; `main` is left equal to upstream). This package is a copy of that branch's `src/index.js` + `LICENSE`, so change the fork and copy again. The starter imports it as a module (`import '@gadxr/aframe-blink-controls'` in `main.ts`). Don't replace it with the CDN copy.
- `packages/aframe-bvh` — fast raycasts against big static meshes with three-mesh-bvh (ours, see its README). Importing it (`main.ts`) patches `THREE.Mesh.prototype.raycast` page-wide (meshes without a tree are unchanged); the `bvh` component builds trees for its entity's meshes (the starter's floor/platforms). Measured on the Mac: the teleport arc over a 2k-triangle terrain went from ~1–1.5 ms to ~0.015 ms per aiming frame. three-mesh-bvh must get A-Frame's three.js: the package depends on `three` as `npm:super-three` at A-Frame's version (so npm A-Frame, the starter, needs nothing); a page with script-tag A-Frame aliases `'three'` in its `vite.config.ts` to a module that re-exports the global `THREE` by name (every name three-mesh-bvh imports). Don't alias `'three'` in a page that imports npm A-Frame: its module build imports `'three'` itself, and the alias makes it wait on its own global.

## Publishing

- Publish with pnpm from the root: `pnpm -r publish` (publishes each package whose version isn't on npm yet; bump `version` by hand first; pnpm refuses unless the tree is clean and on `main`). It needs an npm login with access to the `@gadxr` org. **Not `npm publish`**: npm ignores `publishConfig.exports`, so `@gadxr/ui` would go out pointing at `src/`, which isn't in its `files`.
- Before publishing a change to `@gadxr/ui`, check the tarball: `pnpm pack` in each package, then install the `.tgz` files into a scratch copy of the starter with npm, and run svelte-check and `vite build` there. The packed `package.json` should point `exports` at `dist/`. `dist/fonts.js` keeps Vite's `?url` import of the font, so an app using `@gadxr/ui` needs Vite (it needs vite-plugin-svelte anyway).
- Licenses: MIT. `@gadxr/ui` and `@gadxr/aframe-bvh` have their own LICENSE; blink-controls keeps upstream's. The bundled Geist font is OFL (`assets/Geist-OFL.txt`, published with it).

## Design system (`packages/ui`, `@gadxr/ui`)

- In the workspace and to linked apps it exports its source (`src/index.ts`), so nothing needs building while you work. `pnpm build` (svelte-package; `svelte.config.js` strips the TypeScript) writes `dist/`: `.js`, `.svelte` and `.d.ts` files. `publishConfig.exports` points the published package at `dist/`, and `prepack` builds it. The package has `sideEffects` only for CSS, peer deps `svelte ^5` and `aframe ^1.8` — but the code reads the global `AFRAME`/`THREE` and never imports `aframe` (a page may load A-Frame with a script tag; the starter imports npm A-Frame). The starter (linked to it, see Running) and the gallery (`workspace:*`) import everything from `@gadxr/ui`, including `everyFrame` and `ensure3d`. Paths below are relative to `packages/ui/src`.
- `Scene3D` renders the `<a-scene>` (the starter uses it; other attributes and `on…` handlers pass through to it) and sets it up: children render in 3D, the mouse cursor (`cursor` prop, default `MOUSE_CURSOR`) and scene raycaster (`objects: .raycastable`; the class name is exported as `RAYCASTABLE`), `raycaster.objects` on every `laser-controls` entity once it has loaded (only that property, so its own `far` etc. stay; later-mounted hands are found with a MutationObserver), removing the mouse cursor in an immersive session and restoring it on exit (`mouseCursorInVR` keeps it), `xr.watch`, and loading the pinned troika-text script (`TROIKA_SCRIPT`) before rendering the scene if the page didn't. Logic in `aframe/scene.ts` (`setupScene`, `loadTroika`; tested in `ui-scene`).
- Base UI-style Svelte components that render as HTML, or as A-Frame entities inside `<Scene3D>` (or `<Space3D>`, which only sets the dimension; `dimension="2d"|"3d"` overrides). `Button` (kind/size/shape/isSelected/disabled/inert), `ButtonGroup` (shared props, `mode="radio"|"checkbox"`), `Panel` (`action` corner slot), `Stack`, `Checkbox` (`type="toggle"` for a switch), `Slider`, `Input` (below), `Keyboard`, `Tag`, `Spinner`, `ProgressBar` (`infinite` sweeps), `Avatar` (initials on a color picked from the name, or `src`; `status` dot), `Tooltip` (wraps a trigger; hover after `delay`, focus in 2D, `bind:open`), `Tabs`/`Tab`, `Menu`, `RadialMenu` (hold to open, aim, release: controller trigger + thumbstick in VR, `hotkey` + pointer on desktop), `Modal`, `Toaster` + `toaster.info()/positive()/warning()/negative()`, `Text`, `ThemeProvider`.
- Tokens live in `theme.ts` (px; 3D converts with `space3d.metersPerPx`), override with `createTheme`. Colors/sizes are resolved once for both renderers (`button-style.ts`, `component-style.ts`) — change them there, not in the renderers.
- 3D layout: containers (`Panel`, `Stack`, `ButtonGroup`) call `createStack` + `setStack`; every 3D component calls `useSlot(() => size)` during init and positions an inner entity at `slot()` (`layout.svelte.ts`, math in `layout-math.ts`). A container must call `useSlot` *before* `setStack`. Items can set their own cross-axis `align` (incl. `'end'`; `Stack alignSelf`). To give part of a component's children another stack, or none (placed by hand: Panel's action, Modal), wrap them in internal `StackScope`. `Pressable3D` (internal) is the clickable row behind Tabs and Menu. Text sizes come from `watchTextSize` (troika `synccomplete`).
- 3D hit areas: interactive parts carry `.raycastable` on an entity that owns a mesh (slab, or an invisible `geometry` plane — the raycaster ignores `visible`). Don't put it on a wrapper with no mesh. `Tooltip` adds an invisible hit plane just behind its trigger, so non-interactive triggers (Avatar, Tag) still get hover while a Button in front keeps its own. A picture (`Avatar src`) goes to the material as the loaded `<img>`, not a URL string (A-Frame splits attribute strings on `;`, which breaks data: URLs); an SVG needs `width`/`height` or it uploads blank. 3D Slider drags by intersecting the cursor's ray with the track plane each frame until `mouseup` on the cursor. 3D Modal puts a large dimmed `.raycastable` plane behind its Panel (`catchClicks` stops clicks on the panel reaching it); place the Modal and 3D `Toaster` where the player sees them (e.g. under the camera). In the same page, keep 2D and 3D Modal `open` states separate: an open `<dialog>` makes the canvas inert.
- 3D button = `rounded` slab (carries `.raycastable`; the raycaster only tests meshes set directly on matching entities) + troika label, center-anchored, auto-sized to the measured label. Extra props go on the root (`position`, `mixin`, `id`, …).
- Self-contained: imports only its own files and `svelte*` (`tests/ui-imports.test.mjs` fails otherwise). It registers its `rounded` component itself (`aframe/rounded.ts`, via `ensure3d()`; no script tag needed) and bundles Geist (`assets/`, OFL). `troika-text` stays a script, not bundled (that would pull in a second three.js/A-Frame): a page can load the pinned copy itself so the scene needn't wait, and `Scene3D` adds it if a page doesn't (the starter). Keep new components free of app paths and an app's `public/` scripts.
- `Input` (single line): `label`/`placeholder`/`caption`/`error` (replaces the caption, red border), `bind:value`, `bind:focused`, `inputmode="numeric"` (keyboard opens on 123), `enterkeyhint` (labels the VR enter key: go/send/done…), `maxLength`, `onsubmit` (return `false` to keep editing, e.g. invalid), `blurOnSubmit={false}` (chat: stays open after Send), `oncancel` (Escape / ×: restores the value from before editing). 2D = native `<input>`. 3D = field + `TextLine3D` (troika text clipped with `clipRect`, caret from troika `caretPositions`, scrolls to the caret; a click places the caret). Logic is pure and tested: `text-edit.ts` (every edit is one splice, caret placement/scroll), `keyboard-layout.ts` (pages, shift/caps). One 3D field has focus per page (`textFocus` in `text-focus.svelte.ts`); fields register as an `Editable`, which is all the keyboard and key handling see, so a later multi-line field can plug in. While a 3D field has focus, a window keydown listener in the capture phase takes every key except Cmd/Ctrl shortcuts (a page's own shortcuts and WASD don't fire), and the keyup of each key it took, even after editing ends (A-Frame's `keyboard-shortcuts` acts on keyup: F → enterVR, i.e. fullscreen on desktop); a key already down before focus keeps its keyup; a cursor press (mouse or laser) anywhere but the field or keyboard ends editing. `Keyboard`: place one in the scene (like Toaster); it opens on a `follow` Surface while a 3D field has focus and `xr.immersive`, with a preview line of the text; its backing panel is `.raycastable` so a press between keys doesn't close it. User text goes to troika with `setTroikaValue` (the attribute string splits on `;`).
- `Surface` is the 2D/VR switching unit. Not immersive, placed by `desktop`: `screen` (default) = HTML in a fixed screen region (`screen`, or `target`); `camera` = 3D fixed in front of the camera (`offset`, `desktopScale`, via `ui-attach`). `open` slides it in/out (3D content unmounts once it has slid away; HTML uses a Svelte transition). 3D when `xr.immersive` (a real XR session — `enter-vr` without `scene.xrSession` doesn't count — or `xr.simulated`), placed by `vr`: `world` (its own position), `follow` (lazy follow, `ui-follow`), `hand` (`ui-attach` to a controller; follow when only simulating). Put Surfaces inside `<a-scene>`, not under the camera. Placement math, and which placement applies (`surfacePlacement`), is in `aframe/placement.ts` (tested). The starter's V toggle simulates VR; headless, fake a real session with `scene.xrSession = {…}; scene.states.push('vr-mode'); scene.emit('enter-vr')`.
- `templates/starter` (package `starter`, workspace-only like the library, and only runs inside this workspace) is the app to copy: small, but showing each way to use the library, and the check that the library works in a plain app. `import 'aframe'` in `main.ts` (npm A-Frame 1.8, whose module build sets the `AFRAME`/`THREE` globals; no script tags in `index.html`); `Scene3D` loads troika itself. `App.svelte`: a camera rig with two `laser-controls` hands; Surfaces for each placement (menu `desktop="camera" vr="follow"` with Buttons → `toaster.*` and a 3D `Input`; `screen="right" vr="world"`; `screen="top-left" vr="hand"` with controls for a box in the scene); a plain-HTML toggle outside the scene for `xr.simulated` (V); a `RadialMenu` both ways (E on desktop, right grip in VR); a `.raycastable` entity of its own (the box, floated with `everyFrame`); the menu's `open` on M / left controller Y (`onybuttondown` on the hand); a `createTheme` override; `<Keyboard />`; a `<Toaster />` in a `Surface screen="bottom-right" vr="follow"` (the 3D one under the camera is left commented out as a reference); two `floor` platforms (with `bvh`) and `blink-controls` teleport on the left hand. Keep it free of app code; when a library change adds a way to use it or alters what a page must provide, update the starter and its README.

## Gotchas

- A-Frame's raycaster ignores `visible`; to make something unclickable, remove the `raycastable` class (the cursor targets `.raycastable`).
- A-Frame doesn't keep component values in DOM attributes, so `querySelector('[troika-text*=...]')` won't match; select by id/mixin/structure instead.
- Svelte `onclick` on an `<a-entity>` works (delegated; A-Frame events bubble). Events emitted with `bubbles: false` need a direct listener — Svelte `on<event-name>={...}` attributes compile to one.
- `$state` deep-proxies plain objects: an object stored in one is no longer `===` the original. Use `$state.raw` for state compared by identity (e.g. `textFocus.current`).
- A-Frame's cursor emits mousedown/click on itself with `intersectedEl` (null on empty space) but no `cursorEl`; the copy emitted on the hit entity carries `cursorEl` and `intersection`.
- A cursor on `<a-scene>` (the mouse cursor) also hears every other raycaster's intersection events (they bubble to the scene), so it mirrors the lasers' mouseenter/leave; in VR its own ray also stays frozen where the mouse last was. 3D components keep one `hovered` flag, so its mouseleaves flicker hover off while the laser is still on a button. `Scene3D` removes the mouse cursor during an immersive session (raycaster off first, which sends the leaves) and restores it on exit, unless `mouseCursorInVR` keeps it.
- In an immersive WebXR session the page's `window.requestAnimationFrame` is paused (frames come from the XR session), so per-frame code outside A-Frame's tick must use `everyFrame(scene, cb)` (from `@gadxr/ui`; `packages/ui/src/aframe/frame.ts`) or an A-Frame component. Desktop tests won't catch this.
- Visual orientation of flat UI on the hand: if a rotation shows the back face, directions appear mirrored — fix the entity rotation (flip about an in-plane axis), not with code.

## Testing

- Real VR can't be tested here; say what was verified headlessly and what still needs a headset.
- `pnpm test` runs `packages/ui/tests/*.test.mjs` with Node's built-in runner (no extra deps): radial menu input, `rounded` materials/registration, Surface placement (follow/attach), Input editing and the VR keyboard layout/shift (`ui-input`), design-system tokens, `everyFrame`, Scene3D setup (`ui-scene`: lasers, mouse cursor in VR, troika loading), and the import boundary (they import TS from `../src` via Node type stripping). `tests/helpers.mjs` has `loadThree` (pnpm's `super-three`, found in the workspace root's `node_modules/.pnpm`). Add a test when fixing component logic, and check it fails on the old code.
- blink-controls and bvh have no tests in this workspace yet; check them in the starter (teleport onto the floor and platforms).
- The starter has no unit tests: check it with svelte-check, a scratch build, and headlessly (desktop and IWER, below).
- Emulated headset (closest to a real Quest headlessly): load IWER's browser build (`https://unpkg.com/iwer@2.5.0/build/iwer.min.js`, keep it in a scratch dir, not the repo) as an agent-browser `--init-script` followed by `new IWER.XRDevice(IWER.metaQuest3).installRuntime({ forceInstall: true })` (headless Chrome has its own empty WebXR runtime, so force it), then `document.querySelector('a-scene').enterVR()`. That runs A-Frame's real enter-VR path with controller models and lasers; screenshots show the headset view. To mimic the Quest pausing the page's `requestAnimationFrame` in VR, wrap it to only pass callbacks named `onDeviceFrame` (IWER's frame loop) and **hold** the others, running them on `exit-vr` (dropping them kills A-Frame's render loop after exit). Headless rendering of the app is slow (seconds per frame): wait several seconds after a synthetic mousemove before checking hover.
- Aiming an IWER controller at a 3D target: set `device.controllers.right.quaternion` so the hand's raycaster (`rc.data.origin`/`direction`, in hand space) points at the target. A-Frame tracks the grip pose, which IWER offsets from the pose you set, so take the offset from the current poses (`G = inverse(iwerQuat) * handWorldQuat`, then set `R * inverse(G)`), re-aim over a few frames, and check `raycaster.intersections`. Then `updateButtonValue('trigger', 1)` / `0` clicks.
- Don't drive key shortcuts with `agent-browser press`/`keydown` (or CDP `Input.dispatchKeyEvent` with a guessed `nativeVirtualKeyCode`) on this Mac: one press can turn into thousands of repeated keydowns (a blank page got ~10k in 3 s), so a toggle like V flips endlessly and the page stops answering. Dispatch `KeyboardEvent`s on `document.body` instead (with `code` set; `wasd-controls` reads it). The 3D Input swallows the repeats, so typing tests still pass.
- Toasts last 4 s (`DEFAULT_TOAST_DURATION`), less than a few slow headless frames: check right after the click (e.g. `import()` the `toast.svelte.ts` URL from `performance.getEntriesByType('resource')` and read `toaster.items`), or a working click looks like a failed one.
